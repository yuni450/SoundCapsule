# 홈·캘린더 안정성 점검 결과

기존 기능의 예외 처리만 수정했습니다. Recording 모델, 지도·친구·그룹·설정 기능,
DB 이름과 버전은 변경하지 않았습니다. 사용자 브라우저의 DB를 열거나 초기화하지 않았고,
모든 브라우저 검증은 별도 임시 프로필/IndexedDB와 가상 마이크로 진행했습니다.

## 재현한 문제와 수정

| 문제 | 재현과 원인 | 수정 |
| --- | --- | --- |
| 종료 실패 시 마이크가 켜진 채 UI가 멈춤 | `MediaRecorder.stop()`을 실패시키면 오류 처리에서도 stop을 다시 호출해 예외 발생. 화면 이동 정리도 같은 문제 | 실패 가능한 종료 호출과 트랙·이벤트·타이머 정리를 분리. 종료 예외가 나도 트랙을 닫고 재시도 가능 상태로 복구 |
| 메모 저장 후 화면에 이전 값이 돌아옴 | 저장 후 목록 재조회 완료를 지연하면 dirty가 false로 바뀌는 effect가 오래된 props.memo를 다시 표시 | 저장 API가 반환한 메모를 즉시 표시. 실제로 props.memo가 변경될 때만 외부 변경을 반영하며 편집 중 값은 보호 |
| 알림 차단 시 홈이 사라짐 | BroadcastChannel 생성자가 SecurityError를 던지면 구독 effect가 중단되고 이벤트 해제 함수도 반환하지 못함 | 채널 생성 실패를 격리하고 같은 탭 이벤트·화면 복귀 재조회 및 정상 해제 유지 |
| 손상된 오디오에 재생 오류 안내가 없음 | 비정상 Blob에서 HTMLMediaElement 오류 코드 4가 발생해도 안내가 표시되지 않음 | 공통 AudioPlayer의 error 이벤트에서 안내 표시. Blob 교체 시 오류 상태 초기화 |
| 정상 화면 콘솔에 favicon 404 발생 | 정의하지 않은 /favicon.ico를 브라우저가 자동 요청 | 빈 data favicon을 명시해 불필요한 HTTP 요청 제거 |

## 실행과 결과

Node.js 22.12.0 이상과 개발 의존성을 설치합니다.

```sh
npm ci
npm test
npm run test:browser
npm run build
```

브라우저 테스트는 기본적으로 설치된 Google Chrome을 사용합니다.
별도 테스트 서버를 127.0.0.1의 사용 가능한 포트에서 실행하고 종료 시 정리합니다.
기존 Chrome 프로필이나 개발 서버는 사용하지 않습니다.
Chrome이 없다면 아래처럼 Playwright Chromium을 설치해 사용할 수 있습니다.

```sh
npx playwright install chromium
PLAYWRIGHT_CHANNEL=chromium npm run test:browser
```

다른 실행 파일은 `BROWSER_EXECUTABLE_PATH`로 지정할 수 있습니다.
특정 시나리오만 실행하려면 `npm run test:browser -- --test-name-pattern=모바일`처럼 실행합니다.

| 검증 | 결과 |
| --- | --- |
| 날짜 단위 테스트 | 6개 통과: 윤년·월 이동·현지 날짜·자정·연말·서울/LA 시차 |
| Chrome 브라우저 시나리오 | 13개 통과 |
| 프로덕션 빌드 | 통과 |
| 정상 모바일 터치 시나리오의 콘솔 | 오류/경고 없음 |

브라우저 시나리오에는 다음 검증을 포함합니다.

- 마이크 허용/거부/권한 대기 취소, 늦게 도착한 스트림 해제, 미지원 API 안내
- 실제 MediaRecorder와 가상 마이크의 녹음/미리 듣기/재생/일시정지
- 녹음 중 화면 이동과 새로고침 취소, 연속 시작/종료/저장 시 단일 기록 생성
- 저장 공간 부족 오류 주입, 저장/삭제 실패 시 롤백 및 초안 보존/재시도
- 메뉴 외부 클릭/Escape/방향키, 다운로드 파일명과 원본 바이트 일치, 다운로드 파일 바이트의 재생
- 삭제 확인/취소, 재생 중 삭제 후 플레이어 정리, 다른 기록과 로컬 사용자 ID 보존
- DB v1→v2 업그레이드 시 기존 데이터 보존, 사진과 오디오의 올바른 연결/원자적 갱신
- 사진 추가/미리 보기/새 탭 확대/삭제, 메모 저장/수정/실패, 새로고침 후 유지
- 홈↔캘린더 동기화, 다른 탭의 메모 변경, 기록 삭제 시 관련 사진 Blob 정리
- 오늘만 녹음, 과거/미래 제한, 시작 ISO와 현지 시간 표시, 자정 전 시작·자정 후 저장
- 마이크 권한 대기 중 자정 경과 시 과거 날짜 녹음 차단
- 320/390/1440px 가로 넘침 검사, 터치 에뮬레이션, 제목 100자/메모 500자
- 반복 화면 이동 후 활성 object URL 0개와 변경 알림 리스너 1개 유지

실패 주입은 테스트용 임시 프로필 안에서만 수행합니다. 실제 디스크를 채우거나
사용자의 저장 데이터를 변조하지 않습니다. 리소스 검증은 위 시나리오의 URL/리스너 개수 확인이며,
장시간 녹음의 전체 힙/전력 프로파일링을 완료했다는 의미는 아닙니다.

## 남은 한계와 실제 기기 확인

- 실제 마이크 음질, iOS Safari/Android Chrome의 OS 권한창과 파일 저장 위치,
  기기 잠금/전화 수신/백그라운드 전환/긴 녹음은 실기기에서 추가 확인이 필요합니다.
- 가상 마이크와 모바일 터치 에뮬레이션은 실제 휴대폰 검증을 대체하지 않습니다.
- OS가 저장 전 탭을 강제 종료하거나 모바일에서 beforeunload를 생략하면 초안은 유실될 수 있습니다.
  저장된 기록도 브라우저 데이터 삭제/저장소 회수 시 유실될 수 있으며 서버 백업은 없습니다.
- 같은 메모를 여러 탭에서 동시에 저장하면 마지막 저장이 우선합니다. 자동 병합/충돌 UI는 추가하지 않았습니다.
- 시각은 기기 시계 기준입니다. 기기 시각 오류를 서버로 검증하거나 교정하는 기능은 없습니다.
- 채널 자체가 차단된 환경의 다른 탭 변경은 화면 복귀 재조회로 반영합니다.
- WebM/MP4/HEIC 등의 재생·미리 보기 호환성은 브라우저별로 다를 수 있습니다.
- 이번에 확인한 시나리오에서 수정 후 남은 재현 오류는 없지만, 위 실기기/장시간 조건까지 검증 완료로 간주하지 않습니다.
