# 음표 화면 — 2단계

음표 탭에서 1단계 `getMonthlyPiano` 결과를 그대로 표시합니다.
달성 날짜를 세거나 게이지를 저장하는 별도 UI 집계/저장소는 만들지 않았습니다.
공통 Recording 모델과 3초 녹음 정책, 기존 달성 원장은 그대로 유지합니다.

## 화면과 탐색

- `🎵 나의 음표`, 조회 연월, 이전/다음 달, 현재 달 이동
- 열린 건반 n/7, 월~일 7개 파스텔 세로 건반
- API의 filledSlots/percent로 아래에서 위로 차오르는 색상과 n/4, 퍼센트 표시
- 0/1칸은 잠김 안내, 2~4칸은 연주. 고유 날짜가 5개여도 표시는 4/4
- 과거 달도 조회/연주. 미래 달은 빈 상태로 보여주며 저장 데이터를 조작하지 않음
- 모든 건반 활성화와 모든 게이지 100% 축하를 구분. 동작 줄이기 설정 지원
- 로딩/조회 실패/다시 시도, pending/unresolved 복구 안내와 기록 다시 확인
- 월 이동·화면 복귀·새 달성 알림에서 재조회. 오래된 비동기 응답은 무시
- 로그인 사용자가 바뀌면 이전 사용자의 캐시/연주 상태를 제거

기본 내비게이션은 데스크톱과 모바일 모두 **홈 → 캘린더 → 지도 → 음표 → 친구 → 설정**입니다.
그룹 구현과 라우트는 보존하며, 이번에는 사이드바와 모바일 상단의 **그룹 열기** 버튼으로 접근합니다.
그룹을 친구 내부로 옮기지는 않았습니다. 작성 중 이동 확인과 기존 로그인 접근 제한도 유지합니다.

모바일에서 건반은 한 줄을 유지합니다. 아주 좁은 화면은 키보드 영역만 좌우로 스크롤할 수 있어
페이지 전체가 가로로 넘치지 않습니다. 잠긴 건반도 안내를 확인하도록 포커스/도움말을 제공합니다.
각 키는 상태/진행도/단축키를 스크린리더에 제공하고 안내는 live status로 전달합니다.

## 연주와 음량

| 요일 | 소리 | 키보드 |
| --- | --- | --- |
| 월 | C4 / 도 | A |
| 화 | D4 / 레 | S |
| 수 | E4 / 미 | D |
| 목 | F4 / 파 | F |
| 금 | G4 / 솔 | G |
| 토 | A4 / 라 | H |
| 일 | B4 / 시 | J |

마우스/터치 pointerdown, 키보드, 버튼의 Enter/Space/보조기술 click을 지원합니다.
잠긴 건반은 음원을 만들지 않고 기록 날짜 수·남은 날짜·다음 요일 날짜를 안내합니다.
과거 달에는 소급 녹음을 권하지 않습니다. 입력 필드·IME·수정 키·자동 키 반복에서는 단축키를 무시합니다.

음원 파일 대신 Web Audio의 사인파 4개를 합성합니다.
살짝 비정수인 배음, 8ms 어택과 감쇠 엔벌로프, 로우패스 필터로 부드러운 피아노 계열 음색을 만듭니다.
마스터 컴프레서는 여러 음이 겹칠 때 피크를 줄입니다. 실제 피아노 샘플 녹음은 아닙니다.
7음을 빠르게/동시에 연주할 수 있고 최대 24개 음성으로 리소스를 제한합니다.

- 사용자의 첫 연주 전에는 AudioContext나 oscillator를 만들지 않음
- 연주 이벤트 안에서 suspended context의 resume을 시작해 자동재생 제한에 대응
- 음량 0/음소거 시 새 소리 없음. 기존 소리도 정리
- 창이 비활성화되거나 월/사용자가 바뀌면 재생 중 음 정리
- 화면을 떠나면 oscillator/filter/gain 연결과 타이머를 해제하고 AudioContext 닫기
- 초기화/resume 실패 시 사용자 안내 후 다음 조작에서 재시도
- 초기화 대기 중 이동하면 뒤늦은 음이 시작되지 않도록 세대 번호 검사

참고: [AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume),
[Web Audio 권장사항](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices).

## 검증과 실제 기기 확인

```sh
npm test
npm run test:browser
npm run build
```

브라우저 검증은 별도 Chrome 프로필/가상 마이크와 실제 Web Audio 노드를 사용합니다.
생성한 oscillator의 주파수/횟수, 동시 입력, 음량/음소거, context 닫힘을 확인합니다.
모바일은 터치 에뮬레이션이며 실제 휴대폰 테스트가 아닙니다.
320/390/768/1440px 레이아웃과 데스크톱/모바일 스크린샷도 확인합니다.
최종 결과: 단위 테스트 22개, 전체 브라우저 시나리오 30개, 프로덕션 빌드 통과.
390px에서 7개 건반이 모두 보이도록 간격을 조정한 후 모바일 대상 테스트도 다시 통과했습니다.

실제 스피커/헤드폰의 음질·출력 음량·지연, iOS Safari의 무음 모드/오디오 잠금,
Android 멀티터치, VoiceOver/NVDA 읽기 순서는 실기기/보조기술에서 추가 확인해야 합니다.
오디오 API 검증을 사람이 실제로 들었다는 의미로 표시하지 않습니다.

## 다음 단계 연결점

- 친구/그룹은 현재 props/상태와 GroupsHub 라우트를 유지. 그룹을 친구 탭에 배치할 때 기존 navigate 확인을 재사용
- 설정에서 공통 음량/음소거를 관리하려면 usePianoAudio 설정 전달 지점에 연결. 현재는 화면 내 상태만 사용
- 미확정 이벤트는 기록 다시 확인으로 조회만 하며 날짜를 생성/수정하지 않음. 별도 지원/복구 확정 정책이 필요
- 피아노 달성은 녹음 파일과 독립적. 파일 개수로 게이지를 계산하거나 그룹 공유 시 달성을 새로 만들지 않기
